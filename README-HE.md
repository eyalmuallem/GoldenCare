# GoldenCare — הוראות הקמה והפעלה

GoldenCare היא מערכת Web בעברית לניהול מועדון ספורט. הפרויקט בנוי ב־React + Vite, שומר נתונים ב־Cloud Firestore, משתמש ב־Firebase Authentication ומוכן לפריסה אוטומטית ב־GitHub Pages.

## מה כלול בגרסה הזאת

- התחברות במייל וסיסמה.
- הקמת מועדון על ידי המשתמש הראשון.
- הרשאות נפרדות למנהל ולמאמן.
- ניהול קבוצות, מאמנים, ימים, שעות, מחיר ותקופת פעילות.
- מאגר מתאמנים והורים.
- רישום מתאמן לקבוצה עם מחיר ברירת מחדל, מחיר ידני והנחה באחוזים.
- אמצעי תשלום: הוראת קבע, שיקים או שונות עם פירוט.
- היסטוריית סטטוס חודשית: פעיל, בהפסקה, פעיל ללא חיוב או סיים פעילות.
- יצירת חיובים חודשיים אוטומטית וללא כפילויות.
- בחירת סטטוס התשלום הראשון כבר בעת רישום מתאמן לקבוצה.
- הוראת קבע ושיקים פעילים ממשיכים כברירת מחדל כ״שולם״ בכל חודש, בלי לדרוש סימון מחדש.
- בשיקים קיימת בקרה חודשית נפרדת לסימון שהשיק הופקד.
- תשלום מסוג ״שונות״ נפתח בכל חודש כ״לא שולם״ ודורש אישור ידני.
- תיקון תשלום ידני נשמר רק בחודש שנבחר ואינו נדרס בסנכרון הבא.
- מעקב שולם / לא שולם / חלקי / פטור / לא מחויב, לצד מצב הפעילות.
- סינון לפי סטטוס, מאמן וקבוצה, חיפוש ופרטי קשר.
- מסך נוכחות מודרך לפי תאריך ואימון, כולל הערות וביטול אימון.
- תצוגה מותאמת לטלפון ולמחשב.

## עדכון גרסה 3 — תשלומים ומחיקות

- הוראות קבע ושיקים יכולים לפעול כברירת מחדל חודשית של ״שולם״ לאורך תקופת הרישום.
- שינוי ידני בחודש מסוים הופך לחריגה חודשית בלבד; חודשים אחרים ממשיכים לפי הסדר התשלום.
- ניתן לאפס חריגה ידנית ולחזור לברירת המחדל של הרישום.
- בשיקים נוסף סימון חודשי ״הופקד / טרם הופקד״ ומדד של שיקים הממתינים להפקדה.
- תשלום מסוג ״שונות״ מתחיל כל חודש כ״לא שולם״.
- נוספה מחיקה לצמיתות של מתאמן יחד עם רישומיו וחיוביו. היסטוריית נוכחות שכבר נשמרה נשארת לתיעוד.
- נוספה הסרת מאמן או מנהל מהמועדון, תוך חסימת מחיקה של מאמן שעדיין משויך לקבוצות.
- מחיקת איש צוות משביתה את הגישה במערכת; מחיקת חשבון ההתחברות עצמו עדיין נעשית ב־Firebase Authentication.

חשוב: גרסה זו כוללת הרשאות מחיקה חדשות. לאחר העלאת הקוד יש לפרסם גם את `firestore.rules` המעודכן.

- כל המונחים בממשק הוחלפו מ״ילדים״ ל״מתאמנים״.

# חלק א׳ — הקמת Firebase

## 1. יצירת פרויקט

1. היכנס ל־Firebase Console.
2. לחץ **Create a project**.
3. תן לפרויקט שם, למשל `goldencare-club`.
4. ניתן להשאיר את Google Analytics כבוי בשלב הראשון.

## 2. יצירת אפליקציית Web

1. במסך הראשי של הפרויקט לחץ על סמל ה־Web: `</>`.
2. תן לאפליקציה שם, למשל `GoldenCare Web`.
3. אין צורך להפעיל Firebase Hosting, משום שהאתר יעלה דרך GitHub Pages.
4. Firebase יציג אובייקט בשם `firebaseConfig`.
5. פתח בפרויקט את הקובץ:

```text
public/firebase-config.js
```

6. החלף את כל ערכי `PASTE_...` בערכים שקיבלת. המבנה צריך להישאר כך:

```javascript
window.GOLDENCARE_FIREBASE_CONFIG = {
  apiKey: "...",
  authDomain: "...",
  projectId: "...",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "..."
};
```

הגדרות Web של Firebase אינן סיסמה. ההגנה על הנתונים נעשית באמצעות התחברות וכללי Firestore המצורפים.

## 3. הפעלת התחברות במייל וסיסמה

1. בתפריט Firebase פתח **Authentication**.
2. לחץ **Get started**.
3. עבור אל **Sign-in method**.
4. פתח **Email/Password**.
5. הפעל את האפשרות הראשונה ושמור.

## 4. יצירת Cloud Firestore

1. בתפריט פתח **Firestore Database**.
2. לחץ **Create database**.
3. בחר **Production mode**.
4. בחר מיקום מתאים. חשוב: לא ניתן לשנות את מיקום מסד הנתונים לאחר היצירה.

## 5. פרסום כללי האבטחה

1. בתוך Firestore פתח את הלשונית **Rules**.
2. פתח בפרויקט את הקובץ `firestore.rules`.
3. העתק את כל תוכנו והדבק במקום הכללים הקיימים ב־Firebase.
4. לחץ **Publish**.

הכללים מיישמים את ההפרדה הבאה:

- מנהל: גישה לכל נתוני המועדון.
- מאמן: גישה רק לקבוצות שמשויכות אליו ולרישומי הנוכחות שלהן.
- מאמן אינו יכול לקרוא את אוסף החיובים והנתונים הכספיים.
- משתמש מושבת אינו יכול לגשת לנתונים.

### אפשרות חלופית: פרסום הכללים דרך Firebase CLI

לא חובה, אך אפשר להריץ:

```bash
npm install -g firebase-tools
firebase login
firebase init firestore
firebase deploy --only firestore:rules,firestore:indexes
```

כאשר ה־CLI שואל על קבצים, השתמש בקבצים שכבר קיימים בפרויקט:

```text
firestore.rules
firestore.indexes.json
```

## 6. יצירת משתמש המנהל הראשון

1. ב־Firebase פתח **Authentication > Users**.
2. לחץ **Add user**.
3. הזן את המייל והסיסמה של המנהל הראשון.
4. שמור.

בכניסה הראשונה למערכת המשתמש יראה מסך **הקמת המועדון הראשון**. הוא ימלא את שם המועדון ואת שמו, והמערכת תיצור עבורו הרשאת מנהל.

# חלק ג׳ — העלאה ל־GitHub Pages

## 1. יצירת Repository

1. צור Repository חדש ב־GitHub, לדוגמה `goldencare`.
2. העלה לתוכו את **כל תוכן התיקייה**, כולל:
   - `src`
   - `public`
   - `.github`
   - `package.json`
   - `firestore.rules`
3. אל תעלה את תיקיית `node_modules`.

פקודות לדוגמה מתוך תיקיית הפרויקט:

```bash
git init
git add .
git commit -m "Initial GoldenCare release"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/goldencare.git
git push -u origin main
```

החלף את `YOUR-USERNAME` בשם המשתמש שלך ב־GitHub.

## 2. הפעלת GitHub Pages

1. פתח ב־GitHub את ה־Repository.
2. עבור אל **Settings > Pages**.
3. תחת **Build and deployment** בחר:

```text
Source: GitHub Actions
```

4. פתח את הלשונית **Actions**.
5. Workflow בשם `Deploy GoldenCare to GitHub Pages` יתחיל אוטומטית לאחר Push ל־`main`.
6. בסיום, כתובת המערכת תהיה בדרך כלל:

```text
https://YOUR-USERNAME.github.io/goldencare/
```

הפרויקט משתמש בנתיבים יחסיים וב־Hash Router, ולכן אין צורך לשנות את שם ה־Repository בתוך קוד הפרויקט.

## 3. הוספת דומיין GitHub ל־Firebase Authentication

כדי שההתחברות תעבוד בכתובת החיה:

1. ב־Firebase פתח **Authentication > Settings**.
2. חפש **Authorized domains**.
3. הוסף את הדומיין:

```text
YOUR-USERNAME.github.io
```

אין להוסיף `https://` ואין להוסיף את שם ה־Repository.

# חלק ד׳ — הוספת מאמן או מנהל נוסף

בגרסה הזאת יצירת חשבון ההתחברות נעשית ב־Firebase, והשיוך למועדון נעשה מתוך GoldenCare.

## שלב 1: יצירת החשבון ב־Firebase

1. פתח **Authentication > Users**.
2. לחץ **Add user**.
3. הזן את המייל והסיסמה של המאמן.
4. לאחר השמירה, העתק את ה־UID של המשתמש.

## שלב 2: שיוך המשתמש ב־GoldenCare

1. התחבר כמנהל.
2. פתח **משתמשים והרשאות**.
3. לחץ **שיוך משתמש**.
4. הדבק את ה־UID.
5. הזן שם ומייל.
6. בחר תפקיד `מאמן` או `מנהל`.
7. שמור.

## שלב 3: שיוך המאמן לקבוצה

1. פתח **קבוצות**.
2. צור קבוצה חדשה או ערוך קבוצה קיימת.
3. בחר את המאמן מהרשימה.
4. שמור.

המאמן יראה רק קבוצות שהשדה `coachId` שלהן תואם ל־UID שלו.

# חלק ה׳ — תהליך העבודה החודשי

## בתחילת חודש

1. פתח **מעקב תשלומים**.
2. בחר את החודש.
3. לחץ **יצירת חיובי חודש**.
4. המערכת תעבור על הרישומים התקפים באותו חודש.
5. לכל רישום ייווצר חיוב אחד בלבד.

אם תלחץ שוב על הכפתור, חיובים קיימים לא יוכפלו.

## במהלך החודש

- לחץ על **עדכון תשלום**.
- בחר שולם, לא שולם, חלקי, פטור או לא מחויב.
- בתשלום חלקי הזן את הסכום ששולם.
- הוסף הערה במידת הצורך.
- ניתן לסנן לפי קבוצה וסטטוס ולייצא CSV.

## מתאמן שיוצא או מקפיא פעילות

1. פתח את הקבוצה.
2. לחץ **שינוי סטטוס** ליד המתאמן.
3. בחר סטטוס.
4. בחר מאיזה חודש השינוי חל.
5. שמור.

המערכת שומרת היסטוריית סטטוסים. חיובים שכבר נוצרו אינם נמחקים אוטומטית, כדי שלא תיעלם היסטוריה חשבונאית. ניתן לעדכן אותם ידנית במסך התשלומים.

# פתרון תקלות נפוצות

## מוצג מסך “חיבור GoldenCare ל־Firebase”

קובץ `public/firebase-config.js` עדיין מכיל ערכי `PASTE_...`, או שה־`projectId`/`apiKey` לא הודבקו נכון.

## התחברות עובדת מקומית אך לא ב־GitHub Pages

בדוק שהוספת את `YOUR-USERNAME.github.io` ל־Authorized domains ב־Firebase Authentication.

## Permission denied ב־Firestore

בדוק:

1. שהדבקת ופרסמת את `firestore.rules`.
2. שהמשתמש קיים גם במסך **משתמשים והרשאות**.
3. שהשדה `active` של המשתמש הוא `true`.
4. שלמאמן משויכת הקבוצה המתאימה.

## GitHub Action נכשל בשלב Build

פתח את הלוג תחת **Actions**. בדיקה מקומית בסיסית:

```bash
node -v
npm install
npm run build
```

## שינוי שם Repository

אין צורך לשנות את `vite.config.js`, משום שה־base מוגדר כנתיב יחסי. לאחר שינוי שם ה־Repository יש לבדוק מחדש את כתובת Pages בלבד.

# הערות אבטחה

- אין לפתוח את Firestore עם כלל גורף כמו `allow read, write: if true`.
- אין לשמור סיסמאות בתוך Firestore.
- הסיסמאות מנוהלות רק על ידי Firebase Authentication.
- מומלץ להפעיל מדיניות סיסמה והגנת Email Enumeration בהגדרות Authentication.
- לפני שימוש מסחרי רחב מומלץ לבצע בדיקת אבטחה, גיבויים והגדרת מדיניות פרטיות מתאימה למידע של קטינים והורים.
